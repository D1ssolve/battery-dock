## Исправления 0.1.1

- Исправлена обработка успешной HID-записи, дополненной Windows до длины отчёта устройства.
- Ошибка чтения обнаруженного приёмника больше не считается доказательством отключения устройства.
- Диагностика содержит этап ошибки HID без USB-путей и серийных номеров.
- Оценка G733 явно помечается `≈` в окне и `~` на значке трея. Формула не калибрована под ваш аккумулятор и может заметно отличаться от G HUB. Численные показания не подгоняются по одному сравнению.


Независимый **прототип аналога BatteryOnPC для Windows 11**: заряд беспроводной периферии в системном трее и отдельном окне. Не связан с BatteryOnPC и не использует его бренд, дизайн или исходники.

**Статус: прототип, не готовый проверенный установщик.** Первое аппаратное тестирование 0.1.0 выявило ошибку чтения Aerox 9 и расхождение оценки G733 с G HUB. Исправление HID-записи требует повторной проверки на мыши; точное совпадение процентов G733 не заявляется. Windows GUI требует ручной проверки на Windows; в среде разработки доступны только тесты логики и протокольных фикстур. EXE появляется только после успешной Windows-сборки; её результат проверяйте в GitHub Actions. Показания могут зависеть от ревизии и прошивки устройства.

## Возможности

- Отдельные значки с процентом для каждого обнаруженного устройства; открыть окно можно через меню любого значка.
- Тёмное русскоязычное окно, ручное обновление, интервал опроса 5–3600 секунд.
- Уведомление о низком заряде с настраиваемым порогом. Одно предупреждение за эпизод; повтор после восстановления минимум на 5 процентных пунктов. При зарядке предупреждения подавляются, если устройство сообщает этот статус.
- Отключение и неизвестный заряд отображаются отдельно: старое значение не выдаётся за актуальное.
- Настройки в `%APPDATA%\BatteryDock\settings.json`, атомарная запись.
- Явный демонстрационный режим, безопасный локальный JSON-отчёт без серийных номеров и USB-путей.
- Нет сервера, телеметрии, учётной записи, автоматической установки или изменения автозапуска Windows.

## Устройства и ограничения

| Устройство | Соединение | Показание |
| --- | --- | --- |
| Logitech G733 | родной USB-приёмник, HID++ | **Приблизительный** процент из напряжения; не точный OEM-процент |
| SteelSeries Aerox 9 Wireless | родной 2.4 GHz USB-приёмник | заряд с дискретностью 5% |

Bluetooth, другие устройства, универсальный Bluetooth Battery Service и редактирование прошивки не реализованы. Поддержка этих моделей — реализация известных протоколов, **не гарантия совместимости с вашим экземпляром**. Подробности и источники: [docs/PROTOCOLS.md](docs/PROTOCOLS.md).

## Запуск из исходников

Нужны Windows 11 и **Python 3.11+** с tkinter (официальная установка Python обычно включает его). Запускайте обычным пользователем, права администратора не нужны.

PowerShell, в папке проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m battery_dock
```

Демонстрация интерфейса без доступа к HID:

```powershell
.\.venv\Scripts\python.exe -m battery_dock --demo
```

Диагностика одним опросом без открытия окна:

```powershell
.\.venv\Scripts\python.exe -m battery_dock --diagnose diagnostics.json
```

Также можно запускать `run-windows.cmd` после создания окружения и установки зависимостей. **Не запускайте несколько экземпляров одновременно**: два HID-клиента могут мешать друг другу. Закрытие окна прячет его в трей; команда «Выход» завершает приложение. Если трей недоступен, закрытие окна завершает приложение, а не оставляет невидимый процесс.

Windows может прятать новые значки в меню переполнения: откройте параметры панели задач и включите показ значков Battery Dock. В уведомлениях Windows разрешите уведомления приложению; режим «Не беспокоить» может скрыть предупреждения.

## Сборка EXE на Windows

```powershell
.\build-windows.cmd
```

Можно также дважды нажать `build-windows.cmd`. Скрипт создаёт локальное `.venv`, устанавливает зависимости, запускает тесты и PyInstaller. Результат: `dist\BatteryDock.exe`. Скрипт не устанавливает EXE, не меняет политики безопасности и не добавляет его в автозапуск. Зависимости загружаются из PyPI, версии ограничены диапазонами, но не зафиксированы хешами. Альтернативный PowerShell-скрипт `build-windows.ps1` предназначен для сред, где запуск таких скриптов уже разрешён.

EXE не подписан; SmartScreen может предупредить о неизвестном издателе. Не отключайте защиту системы. Предпочтительнее проверить исходники и собрать приложение самостоятельно. В исходном архиве EXE нет. **Сгенерированный Windows-артефакт** содержит EXE, но даже успешная сборка и автоматическая диагностика не подтверждают работу интерфейса и реальных устройств.

## Автоматическая сборка GitHub Actions

Файл `.github/workflows/build-windows.yml` собирает **Windows x64** на
`windows-latest` с Python 3.12. Сборка запускается при изменении исходников в
ветке `main` или вручную: **Actions → Build Windows EXE → Run workflow**.
Исходники проекта должны находиться в корне репозитория, а не во вложенной папке.

После успешного запуска откройте его страницу и скачайте артефакт
`BatteryDock-Windows-x64-<номер>`. Внутри находится ZIP с `BatteryDock.exe`,
README, лицензией, исходниками приложения, лицензиями зависимостей и архивами
исходников зависимостей (для pystray — полный pure-Python wheel с исходниками). Распакуйте ZIP перед запуском. Python на компьютере
пользователя не нужен. Артефакт хранится 30 дней; это не публикация GitHub Release.
Не распространяйте один EXE отдельно от сопровождающих исходников и лицензий.

Сборка выполняет автоматические тесты, проверку синтаксиса, PyInstaller и
ограниченный 60 секундами запуск готового EXE с `--demo --diagnose`. Этот тест
проверяет запуск замороженного приложения и создание демонстрационного отчёта,
**но не проверяет интерактивный интерфейс или реальные USB-устройства**.
EXE остаётся неподписанным; не отключайте SmartScreen или антивирус.

`BUILD-INFO.json` содержит коммит и версии компонентов, `SHA256SUMS.txt` — хеши
файлов. `requirements-resolved.txt` фиксирует установленные версии конкретной
сборки. Для пересборки можно создать чистое Python 3.12 x64 окружение и установить
этот файл вместо диапазонов `requirements-build.txt`, затем повторить команду
PyInstaller из workflow. Исходники и скрипты лежат в `source/`. SHA-фиксация Actions
не делает сборку полностью воспроизводимой: образ Windows, patch-версия Python и
пакеты PyPI при следующей обычной сборке могут обновиться.

Используются только официальные Actions, закреплённые на проверенные коммиты:
[checkout v4.2.2](https://github.com/actions/checkout/releases/tag/v4.2.2),
[setup-python v5.6.0](https://github.com/actions/setup-python/releases/tag/v5.6.0),
[upload-artifact v4.6.2](https://github.com/actions/upload-artifact/releases/tag/v4.6.2).
Workflow не имеет прав записи в репозиторий и не использует сторонние секреты.

## Если заряд не появился

1. Подключите именно USB-приёмник, включите устройство и подождите один цикл опроса.
2. Разбудите мышь движением. Убедитесь, что подключение не Bluetooth.
3. Закройте второй экземпляр Battery Dock. Если HID занят, временно закройте G HUB / SteelSeries GG и повторите проверку.
4. Сохраните диагностику кнопкой в окне или `--diagnose`. Файл остаётся у вас; перед отправкой просмотрите его.
5. «Нет данных» — это отсутствие корректного ответа, а не 0% батареи. Не делайте выводы о неисправности аккумулятора по этому прототипу.

## Проверка и архитектура

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q battery_dock
```

- `core.py`: модель, валидация, сохранение настроек, предупреждения с гистерезисом.
- `providers.py`: разрешённые HID VID/PID, запросы заряда и проверка ответов.
- `app.py`: tkinter в главном потоке; последовательный HID-опрос в одном фоновом потоке; события трея через очередь.
- `demo.py`: только явные смоделированные данные.
- `tests/`: тесты логики и протоколов без реального оборудования.

### Что проверить на Windows вручную

- Запуск `--demo`, открытие и закрытие окна, повторное открытие из трея, выход из любого меню.
- Настройки: отмена, повторное открытие, невалидные числа, сохранение и перезапуск.
- `--demo --diagnose demo.json`: отчёт явно помечен `demo: true`.
- Реальные устройства: отключение приёмника, выключение устройства, повторное подключение, зарядка, сон и пробуждение Windows.
- Достоверность оценок G733 и шагов Aerox 9 сравнением с приложениями производителя.
- Уведомления, скрытие окна при запуске, многомониторный режим и масштабирование DPI.
- Собранный EXE на чистой Windows 11 без установленного Python.
